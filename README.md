# 🍜 yamyam: 사용자 피드백 라벨링과 LLM 라벨 검증
### 날씨 기반 음식 추천 서비스의 데이터 정제, 피드백 라벨링, LLM 자동 라벨링 검증

날씨로 오늘 먹을 음식(국밥, 칼국수, 냉면, 파전, 팥빙수)과 가까운 강남구 맛집을 추천하는 웹 서비스를 배포하고, 사용자 피드백을 주제별로 라벨링해 서비스 개선에 활용했습니다. 이후 버전마다 달랐던 라벨 기준을 통일하고, LLM 자동 라벨링 결과를 사람의 라벨과 비교해 검증했습니다.

여러 저장소로 나뉘어 있어, 이 저장소에서 전체 흐름을 한곳에 정리했습니다.

- 서비스: https://hwasun-zip.github.io/yamyam-web/

---

## 🔗 저장소 구성

| 단계 | 저장소 | 역할 |
|---|---|---|
| 1. 데이터 정제와 분석 | [yamyam](https://github.com/hwasun-zip/yamyam) | 음식점 인허가 데이터 정제, 상호명 기반 음식 분류, 날씨와 음식 검색량의 관계 검증 |
| 2. 서비스 배포와 개선 | [yamyam-web](https://github.com/hwasun-zip/yamyam-web) | 웹 서비스 배포, 클릭 집계와 설문 수집, 피드백 라벨링으로 v2, v3 개선 |
| 3. LLM 라벨링 검증 | [yamyam-web/feedback-analysis](https://github.com/hwasun-zip/yamyam-web/tree/main/feedback-analysis) | 라벨 기준 통일, Claude 다중 라벨링, 사람 라벨과 비교 |
| (참고) API 서버 | [yamyam-server](https://github.com/hwasun-zip/yamyam-server) | 추천 로직을 REST API로 구현 |

```
음식점 데이터 정제 → 상호명 기반 음식 분류(194곳) → 배포
   → 서술형 의견 라벨링 → v2, v3 개선
   → 라벨 기준 11개로 통일 → LLM 다중 라벨링 → 사람 라벨과 비교
```

## 📌 핵심 결과

**1. 음식점 데이터 정제와 규칙 기반 분류**
- 서울시 음식점 인허가 53.5만 행에서 강남구에 영업중이고 좌표가 있는 10,932곳을 추림
- 상호명 키워드로 5개 음식 카테고리를 붙여, 10,932곳 중 194곳을 추천 후보로 분류
- 빙수는 카페, 파전은 한식 업종으로 등록되는 경우가 많아, 상호명만으로는 해당 매장이 적게 잡히는 커버리지 한계를 확인(팥빙수 5곳, 파전 13곳)

**2. 피드백 라벨링과 개선**
- 클릭 집계(GoatCounter)와 1분 설문을 붙여 배포하고, 첫날 서술형 의견 18건을 주제별로 라벨링
- 가장 많았던 지역 확대 요청(8건)에 맞춰, v2에서 강남구 밖에서도 내 위치 주변을 지도 앱으로 바로 검색하는 기능을 추가
- v2 이후 수집한 의견 8건 중 지역 관련 요청은 1건이었고, 강남구 밖 접속 10회와 내 주변 지도 검색 클릭 9회가 발생
- 가장 많은 요청이 음식 종류(8건 중 6건)로 바뀐 것을 확인해, v3에서 원하는 음식을 직접 골라 맛집을 보는 기능을 추가

**3. LLM 라벨링 자동화와 검증**
- 버전마다 달랐던 주제 목록을 정의가 있는 11개 라벨 기준으로 통일
- Claude가 의견마다 해당 주제를 모두 고르고 근거 구절을 함께 내도록 설계(사람 라벨은 보여주지 않음)
- 서술형 26건 중 24건이 사람 라벨과 완전히 일치했고, 라벨 단위 정밀도 96%, 재현율 100%
- 불일치 2건 중 1건은 당시 기준에 없던 주제, 1건은 한 의견에 섞인 두 번째 요청을 사람이 놓친 경우
- 기준에 없는 요청 5건은 버리지 않고 새 주제 후보로 모음

**4. 추천 근거 검증**
- 974일 검색량과 기상 데이터로, 학습에 쓰지 않은 2025년 243일에서 그날 검색이 가장 많이 늘어난 음식을 58.8% 맞힘(무작위 20%)

## ⚠️ 한계

- 설문 응답은 대부분 지인이며, 서술형 의견은 v1 18건, v2 8건으로 작습니다. 그래서 비율보다 "고친 문제의 불만이 줄고, 고친 기능이 실제로 쓰였는지"로 해석했습니다.
- 클릭은 사람 단위로 이어서 추적하지 않아, 접속과 지도 검색이 같은 사용자의 흐름인지는 확인할 수 없습니다.
- LLM 비교의 사람 라벨은 배포 당시 주제별로 집계한 결과를 바탕으로 응답 단위로 다시 정리한 것이며, 1건은 기록이 없어 추정해 배정했습니다. 불일치 판정도 본인이 했습니다.
- LLM 결과는 1회 실행 기준입니다.
- 추천 모델은 계절과 날씨의 영향을 완전히 분리하지 못했습니다.
